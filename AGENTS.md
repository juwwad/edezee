# AGENTS.md

Guidance for any agent working in this repository. Read this before changing code.

## What this is

Edezee turns a course syllabus into a PowerPoint deck. FastAPI backend in
`backend/`, Next.js frontend in `frontend/`, evaluation harness in `evaluation/`.

The project was built in a five-day sprint. `memory.md` in the repo root holds the
current sprint state. `proposal.md`, `requirements.md`, `architecture.md`,
`design.md`, and `rules.md` are the original specification and are authoritative
on intent. `docs/` holds the as-built documentation.

## Commands

```bash
# Backend
cd backend
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt
./.venv/bin/python -m pytest              # 57 tests, must stay green
./run.sh                                  # serve on :8000

# Frontend
cd frontend
npm install
npx tsc --noEmit                          # typecheck
npm run build                             # production build
npm run dev                               # serve on :3000

# Evaluation (run from the repo root)
backend/.venv/bin/python evaluation/run_eval.py --mode mock    # 12/12, no API key
backend/.venv/bin/python evaluation/run_eval.py --mode live    # needs a running server
backend/.venv/bin/python evaluation/baseline.py                # needs OPENROUTER_API_KEY
```

`make help` lists the same tasks.

## Rules that are not negotiable

- **Secrets.** Never commit `.env`, `.env.local`, or any real key. Configuration is
  environment-only. `.env.example` files ship with empty values.
- **No silent failures.** If a step fails, it must be counted and surfaced. A
  failure the user cannot see is a bug, not a fallback.
- **Tests exercise real code.** Do not mock the pipeline, the parser, the
  validator, or the PPTX writer. Scripted HTTP transports are the only acceptable
  mock, and only at the network boundary.
- **No new scope.** `requirements.md` §5 lists the non-goals. Do not add accounts,
  persistence, layout options, or a chat interface.
- **Semantic commits.** `feat:`, `fix:`, `docs:`, `refactor:`, `chore:`.

## Architecture invariants

Breaking any of these silently degrades quality, and the tests may still pass.

1. **One model call per topic.** Never batch a whole syllabus into one prompt. The
   baseline comparison in `evaluation/baseline.py` is the evidence for why.
2. **A deck always finishes.** A topic that fails all retries becomes a flagged
   placeholder slide. It never aborts the run.
3. **Research is optional.** Clearing `TAVILY_API_KEY` must leave the product
   working, with slides tagged `model-knowledge`.
4. **Provenance is recorded per slide.** `grounding` is `research`,
   `model-knowledge`, or `placeholder`, and it is always set.
5. **HTTP clients are pooled.** `LLMService._http()` and `ResearchService._http()`
   reuse one client. Creating a client per call adds a TLS handshake per topic.
6. **Bullets are trimmed, never rejected.** Overflow past 5 bullets is trimmed by a
   validator. Do not reintroduce `max_length` on `bullet_points`.

## Where to make a change

| Change | File |
| --- | --- |
| New syllabus format (numbering, headers) | `backend/app/services/parser.py` + `tests/test_parser.py` |
| Prompt or JSON contract | `backend/app/services/llm.py` + `tests/test_llm.py` |
| Retry, fallback, or degradation policy | `backend/app/services/pipeline.py` |
| Slide layout, fonts, geometry | `backend/app/services/pptx_service.py` |
| HTTP contract or status codes | `backend/app/main.py` + `tests/test_api.py` |
| UI copy, states, or layout | `frontend/components/` |
| API client or types | `frontend/lib/api.ts` |
| Test cases or rubric | `evaluation/cases/test_cases.json` + `evaluation/run_eval.py` |

## Before you claim something works

1. Run the command and read the raw output, including the exit code.
2. Confirm the artifact exists. "The deck generated" means the file opens and its
   slide text was printed, not that a request returned 200.
3. Ask what would make your claim false, then test that.

`evaluation/run_eval.py --mode mock` is the quality gate. It needs no API key and
must pass 12/12. If it fails, treat that as the top priority.

## Known environment quirks

- `next-env.d.ts` is gitignored and generated by `next build`. `npx tsc --noEmit`
  can fail before the first build. Expected, not a regression.
- `--mode live` needs `OPENROUTER_API_KEY` and network access. Without it, use
  `--mode mock` and say so rather than reporting a failure.
- The frontend reads `NEXT_PUBLIC_API_BASE_URL` and builds fine without a running
  backend.
- There is no CI. Local checks are the only gate, so run them properly.
