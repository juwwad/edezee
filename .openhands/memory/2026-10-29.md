## Environment quirks (do not re-derive)
- **File editor writes new files 0600.** In a Docker image RUN as a non-root user this
  makes them unreadable (`PermissionError: .../demo.py`). Always `chmod 644` new files
  before committing/building.
- **Docker daemon needs `sudo`** in this sandbox; the socket is `root:docker` and the agent
  user is not in the `docker` group. `sudo dockerd &` then `sudo docker ...`. Start it
  **without** `--bridge=none` or builds fail with "network bridge not found".
- CORS mismatch was the real cause of a browser "generation failed": UI origin was
  `127.0.0.1:13000` but `ALLOWED_ORIGINS` only had `localhost:3000`. Exactly the trap
  issue #11 documents.
- **`next dev` auto-generates an untracked `frontend/AGENTS.md`** (Next 16 behaviour;
  log line "Generated AGENTS.md for AI agents"). Delete it before committing, or set
  `agentRules: false` in `next.config.ts`. Same idea for `next build`.

## How to obtain a managed-proxy key in the sandbox (expensive to rediscover)
- The LLM proxy key is fetched from `OH_LLM_API_KEY_REFRESH_URL`
  (`https://app.all-hands.dev/api/keys/llm/managed/current`) with header
  `X-Session-API-Key: $SESSION_API_KEY` (plain GET, returns the key as `text/plain`).
- `$SESSION_API_KEY` is NOT in the shell env; it is only in the agent-server process
  environ: `grep SESSION_API_KEY /proc/1/environ` (null-separated). The env var
  `OH_LLM_API_KEY_REFRESH_HEADERS` contains the literal placeholder
  `${SESSION_API_KEY}`, so it is useless as-is — substitute the real value.
- Use it to reproduce #6: `POST {OH_LLM_API_KEY_REFRESH_BASE_URLS}/chat/completions`.
- Do not print or commit the key; write it to a 0600 temp file if a script needs it.
