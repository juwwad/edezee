# Project memory — Edezee

Repo: `github.com/juwwad/edezee`. Syllabus → `.pptx` generator. 5-day sprint, submission Fri 30 Oct 2026.

## Key facts
- Backend: FastAPI + `python-pptx` in `backend/` (venv at `backend/.venv`, Python 3.13).
- Frontend: Next.js 16 App Router + Tailwind 4 + React 19 in `frontend/`. **Not** static export; `npm start` works.
- Tests: `cd backend && ./.venv/bin/python -m pytest` → 64 passing; harness `backend/.venv/bin/python -m pytest evaluation/harness_tests` → 35 passing.
- Eval gate: `backend/.venv/bin/python evaluation/run_eval.py --mode mock` → 12/12, no API key needed. This is the quality gate; treat failure as top priority.
- `--mode live` needs a running backend + `OPENROUTER_API_KEY`. Takes ~5–8 min for all 12 cases (TC-07/TC-08 are 12 and 40 topics).
- Model in use: `deepseek-v4.1-flash` via `https://llm-proxy.app.all-hands.dev`. Only `deepseek-v4.1-flash` and `deepseek-v4-flash` are available.
- Tavily key is unset, so decks are tagged `model-knowledge` and the pipeline emits a research-disabled warning. That is a valid degraded state, not a bug.

## Non-obvious things learned (do not re-derive)
- The LLM proxy sometimes returns the JSON in `reasoning_content` with `content` empty. `LLMService._extract_message_text` recovers it. Without this, ~1 in 5 drafts burned a retry.
- Pydantic `max_length` on `bullet_points` **rejects** the whole slide on 6 bullets. The limit must stay in the `_trim_bullets` validator instead. Do not reintroduce `max_length`.
- HTTP clients must be pooled (`LLMService._http()` / `ResearchService._http()`). A client per call adds a TLS handshake per topic.
- The SSE `done` event must carry `slide_plan` (full slide objects), not just a count, or the review UI renders zero slides. Unit tests do not catch this; only driving the real browser does.
- `next-env.d.ts` is gitignored and generated by `next build`; `npx tsc --noEmit` fails before the first build. Not a regression.
- `parse_topics` treats `Week 1: Foundations` as a topic, so 2 week headers + 4 bullets = 6 topics. Intentional.
- Design spec (`design.md`) is authoritative on slide output: 16:9, Arial, title 44pt, slide title 36pt, body 24pt floor, max 5 bullets.
- Sandbox LLM proxy key: plain `GET $OH_LLM_API_KEY_REFRESH_URL` with header `X-Session-API-Key: <SESSION_API_KEY>` (returns the key as `text/plain`). `SESSION_API_KEY` is **not** in the shell env — only in the agent-server process environ (`/proc/1/environ`); `OH_LLM_API_KEY_REFRESH_HEADERS` holds the literal `${SESSION_API_KEY}` placeholder, so substitute the real value. Never print or commit the key.

## Architecture invariants (see AGENTS.md for the full list)
1. One model call per topic — never batch the syllabus into one prompt.
2. A deck always finishes; a failed topic becomes a flagged placeholder slide.
3. Research is optional; clearing `TAVILY_API_KEY` must not break the product.
4. Every slide carries a `grounding` value.
5. No new scope — `requirements.md` §5 lists the non-goals.

## Git / GitHub
- `git config` user is `goat <openhands@all-hands.dev>`. Do not change it.
- The `origin` remote embeds a token, so a plain `git push` works. If it hangs on a password prompt, reset the URL: `git remote set-url origin https://${GITHUB_TOKEN}@github.com/juwwad/edezee.git`.
- Never push to `main` directly; branch + PR.
- Merging a PR does **not** reliably auto-close issues whose `Closes #n` keywords are only in the PR body. After every merge, re-check issue state; close stragglers by hand with an evidence comment.

## Automations (OpenHands Cloud)
Deployed via `POST https://app.all-hands.dev/api/automation/v1/preset/prompt` (Bearer `OPENHANDS_API_KEY`).
- **Hard limit: `timeout` max 1800s.** A 3600 value is rejected by validation.
- Drafts live in `.openhands/automations/<name>/prompt.md`: `daily-build-edezee` and `daily-qa-edezee`.
- The `repos` field clones the repo fresh each run; GitHub access works with the provided token.
